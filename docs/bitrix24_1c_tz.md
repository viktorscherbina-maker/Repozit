# Техническое задание

## Интеграция Битрикс24 с 1С и настройка процессов Битрикс24

### 1. Цель проекта

Настроить в Битрикс24 процесс согласования коммерческих предложений в сделках и интеграцию с пятью базами 1С для автоматического создания документа `Счёт на оплату`, передачи товарной части и обратной синхронизации созданных документов в смарт-процесс `1С документы`.

### 2. Границы работ

- Настройка бизнес-процесса согласования КП в сделках.
- Создание или настройка смарт-процесса согласования КП, привязанного к сделке.
- Настройка смарт-процесса `1С документы`.
- Настройка справочника 1С-баз с GUID.
- Реализация маршрутизации запросов в одну из 5 баз 1С по бренду продукта.
- Передача товаров и услуг из товарного каталога Битрикс24 в табличную часть документа 1С.
- Создание записи в Битрикс24 по документам, созданным в 1С, с привязкой к исходной сделке.

### 4. Бизнес-процесс согласования КП

Процесс строится на бизнес-процессах Битрикс24. Согласование КП запускается из сделки и ведётся в отдельном смарт-процессе, привязанном к исходной сделке. По итогам согласования результат возвращается в сделку.

| Шаг | Описание | Результат |
|---|---|---|
| 1 | Менеджер заполняет сделку, товары, сумму и условия КП | Сделка готова к согласованию |
| 2 | Запускается бизнес-процесс согласования | Создаётся элемент смарт-процесса согласования КП |
| 3 | Согласующий принимает решение | Согласовано, отклонено или требуется доработка |
| 4 | Результат передаётся в сделку | Стадия сделки обновляется согласно результату |
| 5 | После согласования сделка может перейти на этап N | Запускается интеграция с 1С |

### 5. Логика интеграции со 1С

При переходе сделки в воронке `Сделки` на этап N запускается скрипт или робот, который отправляет запрос в выбранную базу 1С на создание документа `Счёт на оплату`. База 1С определяется по значению поля `Бренд продукта`.

| Условие | Действие |
|---|---|
| Сделка перешла на этап N | Запустить интеграционный скрипт |
| В сделке указан бренд продукта | Определить базу 1С по таблице маршрутизации |
| В сделке заполнены товары/услуги | Передать товарные строки в табличную часть документа 1С |
| Контрагент — контакт | Передать как физическое лицо |
| Контрагент — компания | Передать как юридическое лицо |
| 1С вернула созданный документ | Создать или обновить элемент смарт-процесса `1С документы` |
| 1С вернула ошибку | Зафиксировать ошибку и уведомить ответственного |

### 18. Требования к логированию и защите от дублей

- Фиксировать ID сделки, выбранную базу 1С, дату и время отправки запроса.
- Хранить статус отправки и текст ошибки при неуспешном ответе.
- Проверять дубли по связке: ID сделки + тип документа + база 1С.
- Предусмотреть ручной повтор отправки после исправления ошибки.
- Не создавать повторный счёт при повторном переходе на этап N, если документ уже создан.

### 19. Критерии приёмки

| № | Критерий | Ожидаемый результат |
|---|---|---|
| 1 | Сделка переходит на этап N | Запускается интеграционный скрипт |
| 2 | В сделке указан бренд продукта | Запрос уходит в корректную базу 1С |
| 3 | В сделке заполнены товары/услуги | Позиции передаются в табличную часть документа 1С |
| 4 | Контрагент является контактом | В 1С передаётся физическое лицо |
| 5 | Контрагент является компанией | В 1С передаётся юридическое лицо |
| 6 | 1С успешно создала счёт | В Битрикс24 создан элемент `1С документы` с привязкой к сделке |
| 7 | 1С вернула ошибку | Ошибка записана, ответственный уведомлён |
| 8 | КП согласовано через смарт-процесс | Результат согласования отражён в сделке |

### 20. Открытые вопросы для заполнения

- Указать точные названия и GUID пяти баз 1С.
- Заполнить соответствие брендов продуктам и базам 1С.
